# Flutter VibeCoding 完整学习计划

> 适用对象：Flutter 新手，但已有 5 年 Web 开发经验
> 
> 学习目标：用 **VibeCoding** 的方式学习 Flutter——不是“先啃完所有语法再写项目”，而是通过 **小步快跑、AI 协作、每日打卡、每周实战、持续复盘** 的节奏，系统掌握 Flutter 开发。

---

# 1. 什么是 Flutter 学习中的 VibeCoding

VibeCoding 不是“让 AI 替你写完代码”，而是：

1. **你负责目标、判断、取舍、验收**
2. **AI 负责拆解、讲解、生成初稿、陪练、复盘**
3. **每次只推进一个很小的功能闭环**
4. **每次练习都要可运行、可解释、可改造**
5. **始终从“做东西”里学习，而不是孤立记忆 API**

对于有 Web 开发经验的人，Flutter 学习的关键不是“编程基础”，而是完成以下心智转换：

- 从 HTML/CSS/JS 的 DOM 思维，切到 **Widget 树思维**
- 从“页面 + 样式分离”的习惯，切到 **声明式 UI 组合**
- 从“浏览器运行环境”，切到 **跨平台渲染与移动端交互**
- 从“已有丰富生态直觉”，切到 **理解 Flutter 自带组件体系和状态模型**

所以，这份计划不会让你从最简单的变量、循环开始，而是围绕下面四条主线推进：

- **UI 搭建能力**
- **状态管理能力**
- **数据与接口能力**
- **真实项目落地能力**

# 2. 总体学习路线图

我建议采用“**4 周核心版 + 8 周扩展版**”的结构：

## 第一层：4 周核心版
目标：快速建立 Flutter 全局认知，能独立做出 2~3 个小项目。

- 第 1 周：Flutter 基础、Widget 思维、布局、交互
- 第 2 周：页面组织、状态管理入门、表单与列表
- 第 3 周：网络请求、异步、项目结构、基础工程化
- 第 4 周：综合实战，完成一个可展示 Demo

## 第二层：8 周系统版
目标：能比较稳定地做中小型 App。

- 第 5 周：状态管理进阶（Provider/Riverpod/BLoC 认知）
- 第 6 周：本地存储、路由、主题、组件抽象
- 第 7 周：复杂页面、性能优化、错误处理、测试入门
- 第 8 周：完整项目实战、打磨、发布准备

## 第三层：12 周深度扩展版
目标：具备真实业务开发能力。

- 动画
- 平台能力调用
- 架构设计
- 多环境配置
- CI/CD
- 打包发布
- 团队协作规范

# 3. 学习原则：你每天该怎么学

每天遵循 4 段式：

## 3.1 输入（20%）
快速理解当天核心概念，不追求面面俱到。

## 3.2 跟做（30%）
让 AI 先给出最小可运行示例，你边看边改。

## 3.3 改造（30%）
必须在示例上做 2~3 次变体修改，把代码变成自己的。

## 3.4 输出（20%）
完成打卡记录：今天学了什么、哪里不懂、下次要问什么。

# 8. 每天固定可复用的 10 类提示词

## 1）概念理解型

```text
请用“我有 5 年 Web 开发经验，但刚学 Flutter”的背景来解释这个概念：___。
要求：
1. 用 Web 类比
2. 给最小代码示例
3. 说明常见误区
4. 说明真实项目里怎么用
```

## 2）页面搭建型

```text
请带我一步步搭建一个 Flutter 页面：___。
要求：
1. 先拆页面结构
2. 再分步骤写代码
3. 每一步都解释为什么这样写
4. 最后给我 3 个样式改造练习
```

## 3）组件拆分型

```text
请帮我判断这个 Flutter 页面该怎么拆组件。
我希望你输出：
1. 哪些部分应该拆成 widget
2. 为什么拆
3. 拆完后的目录结构建议
4. 初学者常见的过度拆分问题
```

## 4）Bug 调试型

```text
你现在是我的 Flutter 调试助手。
下面是我的报错信息/现象：___
请你：
1. 先判断最可能的 3 个原因
2. 按排查优先级给出步骤
3. 每一步告诉我应该看哪里
4. 不要一上来就重写代码，优先帮我定位问题
```

## 5）代码讲解型

```text
请你逐段解释这段 Flutter 代码在做什么，并重点说明：
1. 状态在哪里
2. UI 为什么会这样更新
3. 哪些写法适合新手
4. 哪些地方以后应该重构
代码如下：
```

## 6）重构型

```text
请帮我把这段 Flutter 代码重构得更清晰，但不要过度设计。
目标：
1. 保持初学者可理解
2. 提高结构清晰度
3. 拆出合适的 widget / model / service

```

## 7）项目拆解型


## 8）复盘型

```text

学习记录：___
请输出：
1. 我今天真正掌握了什么
```

# 10. 你作为 Web 开发者的优势与补课重点

## 你的优势
- 组件化思维已经具备
- 接口、状态、交互概念不陌生
- 调试与工程化意识更容易建立
- UI 结构抽象能力更强

## 你需要特别补的
- Flutter 布局约束系统
- Widget 树思维
- 状态更新机制
- 移动端交互习惯
- Dart 语言细节
- Flutter 工程组织方式

你最容易掉进的坑不是“不会写代码”，而是：

- 用 Web 思维强行套 Flutter
- 过早追求架构完美
- 一上来就学太多状态管理方案
- 看懂示例但不做二次改造

所以记住一句话：

> **先用 setState 做出功能，再理解为什么后面需要 Provider/Riverpod。**
