# 2. 每个项目的实战结构模板

任何项目都建议按下面 6 步推进：

1. **定义 MVP**
   - 只保留最核心功能

2. **拆页面**
   - 列出页面清单

3. **定数据结构**
   - model 怎么设计

4. **先做 UI**
   - 先跑起来再美化

5. **再做交互**
   - 新增、删除、跳转、提交

6. **补异常与优化**
   - loading、empty、error、重构

# 4. 题库式训练方式

每个项目都建议按下面 4 个问题去训练自己：

1. **我今天要解决什么最小问题？**
2. **我现在是在做 UI、交互还是数据？**
3. **我能不能先写最小可运行版本？**
4. **我做完后能不能改 2~3 次？**

如果这 4 个问题都答不上来，说明项目目标太大了，需要继续收缩。

# 5. 可直接复用的项目拆解提示词

## 5.1 项目收敛提示词

```text
你是我的 Flutter 产品经理 + 导师。
我要做一个 Flutter 小项目：___。
请你先帮我把需求收敛成 MVP，只保留最核心的 3~5 个功能。
输出：
1. 项目定位
2. MVP 功能清单
3. 非 MVP 功能清单
4. 页面清单
5. 数据结构建议
6. 开发优先级
```

## 5.2 项目拆天提示词

```text
请把这个 Flutter 小项目拆成 7 天可执行计划。
要求：
1. 每天只有一个最小交付目标
2. 每天都要有自测标准
3. 每天都要附一个适合新手的提示词
4. 第 7 天必须有复盘
```

## 5.3 项目陪练提示词

```text
请作为我的 Flutter 结对编程助手，陪我完成这个项目。
要求：
1. 每次只推进一个小模块
2. 先解释，再给代码
3. 代码要尽量保持初学者可读
4. 每个模块都告诉我它在练什么 Flutter 核心能力
5. 如果我卡住，请先帮我定位问题
```

## 5.4 项目升级提示词

```text
请把这个 Flutter 小项目从“练习版”升级为“作品版”。
请从以下维度给建议，并按优先级排序：
1. UI
2. 交互
3. 状态
4. 异常处理
5. 代码结构
6. 可展示性
```

# 7. 每个项目的验收标准

每次做完一个项目，至少回答以下问题：

- 是否能独立运行？
- 是否有清晰的页面结构？
- 是否完成了核心功能？
- 是否至少做了 2 处自己的改造？
- 是否能说清楚状态在哪里？
- 是否能解释页面数据如何流动？
- 是否有基本的异常处理？

如果不能回答清楚，说明这个项目还不算真正完成。

# 8. 适合你这种 Web 开发者的训练建议

你最适合的训练方式不是“看完再做”，而是：

- 看一个最小示例
- 复制跑通
- 改 2~3 次
- 写一段自己的复盘
- 再把它升级成小项目

因为你已经有前端基础，真正需要补的不是“写页面”，而是：

- Flutter 的布局约束
- Widget 树思维
- 状态驱动 UI
- 数据流组织
- 项目分层习惯

所以请始终记住：

> 不是项目越大越好，而是每次都要比上一次更理解 Flutter 一点。
